# 服务器和诊断

![服务器](/images/servers.png)

**服务器** 页列出所有接入的 VPS：

| 列 | 说明 |
| --- | --- |
| 状态 | 待接入（还没执行安装命令）、在线、离线（超过三个同步间隔没有联系） |
| 主机名、PSM、Agent | 服务器报告的主机名、PSM 版本（日期和提交号）、psm-agent 版本；版本落后于面板期望的那个时标上 **可升级** |
| 本月流量 | 这台服务器上所有节点的合计 |

## 诊断

点 **诊断**，psm-agent 在下一次同步时收集并发回：

- PSM 和 psm-agent 的版本；
- 三个内核是否安装、版本、是否在运行；
- 独立安装的 Snell / SS2022 的状态；
- PSM 里的节点数；
- `psm doctor` 的检查结果，需要注意的项目会列出来。

服务器离线或出问题时，先看这里；更详细的信息在服务器上执行 `psm doctor`。

## 升级 psm-agent

面板期望所有服务器运行同一个 psm-agent 版本。某台服务器报告的不是它时，Agent 列标上 **可升级**，操作栏多出 **升级 agent**（只对在线的服务器显示）。

点它之后，那台服务器依次做三件事：更新 PSM（要装哪个 psm-agent 版本写在 PSM 里，所以顺序不能反）、按发布页的 SHA256SUMS 校验并替换 psm-agent、重启服务。节点、中转和流量统计都不受影响，转发不会中断。

psm-agent 会**先把结果报给面板，再动手**——它重启的是自己，晚一步就没人能报告了。所以操作记录里的成功只表示"升级已开始"；真正完成的标志是 Agent 列在下一次同步后变成新版本，通常十几秒。万一失败，在服务器上执行 `psm agent upgrade` 能看到原因。

离线的服务器没有这个按钮（任务只会一直排队）。手工的办法仍然可用：生成安装命令执行一次，或在服务器上直接执行 `psm agent upgrade`。

::: warning 0.10.1 之前的 agent 用不了这个按钮
"升级"本身是下发给 psm-agent 的一个任务，**0.10.1 之前的版本不认识它**，收到只会回一句"不支持的任务"。这些服务器先手工升一次：重跑一次安装命令，或者在服务器上先更新 PSM（`psm` 菜单里的更新）再执行 `psm agent upgrade`——`psm agent upgrade` 这条命令本身也是随 0.10.1 才有的，所以第一次得让 PSM 先更新。之后的每次升级都可以在面板上点按钮了。
:::

## 移除服务器

点 **移除**：

- **在线的服务器**：状态变成"卸载中"，psm-agent 在服务器上删除所有由面板建的节点、独立安装的 Snell / ss-rust **和中转规则**，把结果报给面板，然后卸载自己（服务、程序和配置都删掉）。完成后服务器从列表消失，操作记录里写着删掉了什么。**PSM 本身、内核和你在服务器命令行里建的节点会保留。**
- **离线的服务器**（或一直停在"卸载中"）：只能从面板移除，服务器上的节点、中转和 psm-agent 保留。之后在服务器上执行 `psm agent remove --yes` 卸载 psm-agent；节点用 `psm` 菜单或 `psm node delete` 删除，中转用 `psm relay delete` 删除。
- **还没接入的服务器**：直接删除。

在面板上 **删除节点** 时，服务器上的节点（独立安装的 Snell / ss-rust 则是整个程序）也会一起删除，流量统计随之移除。中转同理，realm 的转发规则一起删掉。

::: tip 一直停在"删除中"怎么办
删除要交给那台服务器执行，所以服务器离线时会停在**删除中**，等它回来就自动完成。如果这台机器再也回不来了，按钮会变成 **强制移除**，再点一次就把这条记录从面板上抹掉。这只是面板侧的清理：机器如果还在，上面的节点和转发规则要自己用 `psm node delete` / `psm relay delete` 处理。
:::

## 同步间隔

psm-agent 空闲时每 30 秒联系一次面板，有任务时每 3 秒一次。每次联系是一次 Worker 请求加一次 D1 写入，按 30 秒计一台服务器每天约 2900 次，免费额度够三十多台服务器。服务器更多时，把 Worker 变量 `SYNC_INTERVAL` 调大（最大 300）。
